## Web fetches through the proxy (v0.19.0 — merged into main, tag v0.19.0)

The owner's first v0.18.0 batch log (2026-09-29): every `x.com` / `t.co` / `youtu.be` link failed with `[WinError 10061] No connection could be made because the target machine actively refused it` while `gooseworks.ai` fetched full — the blocked-web signature (poisoned local DNS refuses the connection). The app's proxy (v2rayN SOCKS5 `127.0.0.1:10808`) carried Telegram since v0.07.1 but never web fetches.

- **`web_fetch.py`**: `proxy_from_config` (the `proxy.use_for_web` toggle, **default ON** so the owner's existing config gets the fix with no Settings visit), `web_proxy_preflight` (TCP probe + PySocks import check, never raises), the PySocks connection classes — `rdns=True`, the hostname reaches the proxy and is resolved AT THE EXIT (the actual fix; `http://`-type proxies get the same via urllib's `ProxyHandler` absolute-URI requests) — and `fetch_url(proxy=)`. Loopback targets are NEVER proxied (v0.15.1 rule, `ProxyHandler({})` forced). Every proxy failure is a normal failed `FetchResult` whose reason names the proxy — one bad proxy never kills a batch. The instance-attribute trap is pinned by test: `HTTPConnection.__init__` binds `socket.create_connection` on the instance, so the socks override re-binds after `super().__init__()`.
- **`website_pipeline.py`**: constructor pre-flight — proxy up → `🌐 Web fetches via SOCKS5 127.0.0.1:10808 (Settings → 🌐 Proxy)` + a proxied fetcher; down → one loud warning + DIRECT fallback (the batch never blocks). NEVER applied to an injected `fetch_fn` (the golden run stays offline). **Retry re-arm**: `WebsiteStateDB` grows `website_state_meta` (`get_meta`/`set_meta`) + `rearm_retries`; when the ACTIVE proxy epoch (type:host:port) differs from the stored one, the whole retry queue resets (attempts → 0, due NOW) — the owner's 263 failed links retry through the tunnel on the next batch instead of marching to the 3-attempt freeze. Once per epoch, failure-tolerant.
- **GUI**: Settings → 🌐 Proxy grows `proxy_use_for_web` ("Use this proxy for web fetches too (Websites pipeline — x.com / YouTube need it)", default checked, tooltip names the loopback rule); carried by `save_config` + `_get_proxy_dict`; `CONFIG_EXAMPLE` defaults in both constants modules; `PySocks>=1.7.1` in requirements.txt (a hard Telethon dependency, now explicit).
- **Tests**: `tests/test_webproxy.py` (44) — the config contract (missing key = ON; opt-out; hostile blocks), a REAL fake SOCKS5 server (greeting → CONNECT → tunneled HTTP) proving the hostname reaches the proxy (rdns) and the loopback bypass (a separate plain HTTP server; the SOCKS server sees nothing), a fake HTTP proxy proving absolute-URI requests, pre-flight alive/dead/PySocks-missing, opener wiring (incl. the empty-`ProxyHandler` suppression quirk), pipeline integration (proxied fetcher / direct fallback / opt-out / injected-fn verbatim / disabled), the re-arm epoch rules (first, same-epoch, changed-epoch, failure-tolerated), GUI source assertions, defaults + packaging.
